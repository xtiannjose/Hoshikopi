# Deep check, 2026-11-17

> **In plain words:** after the November audit backlog was finished (Phase 10), the whole app was checked again from top to bottom, the way a senior security reviewer, a senior QA tester and a senior developer would check it. Nothing serious was found: no security hole, no way to lose money or anyone's data, and every earlier fix still holds. The check found 46 smaller problems. They are listed below in plain words, grouped into five fix batches (Phase 11 in the [roadmap](../07-ROADMAP.md)).
>
> **Who should read it:** the owner deciding what to fix next; a developer picking up a fix batch.
> **Last checked:** 2026-11-17.

## 1. What was checked, and how

The check ran on the code as it stood after pull request #110 (`feature/10.21-docs`), in two parts.

**Automatic checks**, all run on 2026-11-17:

| Check | What it does | Result |
| --- | --- | --- |
| Lint and format (`eslint`, `prettier`) | Looks for code mistakes and messy formatting | Clean |
| Type check (`tsc`) | Makes sure every piece of code is used with the right kind of data | Clean |
| Unit and database tests (Vitest) | 484 small tests of the rules (prices, Stars, Order Status...) against a real test database | 484 passed |
| Browser tests (Playwright) | 318 tests that click through the real site in a browser, on a phone width and a desktop width, with accessibility checks (axe) | 248 passed, 70 skipped on purpose (each runs at the other width), 0 failed |
| Known security advisories (`npm audit`) | Compares every library the site uses with public lists of known holes | 0 found |
| Secrets scan | Searched every file and the whole git history for passwords and keys | None. The only match is a made-up test value |
| Database migrations | Checks the local database has every schema change | Up to date (16 migrations) |
| Live site | Opened 19 pages and checked the security headers on https://hoshikopi.vercel.app | All pages answer; HTTPS, CSP, frame and content-type protections on; the daily job refuses calls without its secret |

**Reading the code**: six reviewers (Claude agents, each with one area) read every module, page and Server Action, traced each problem end to end, and wrote a concrete "this is what goes wrong" for it. Every finding below was then checked against the code a second time before it was written down. The areas:

1. Ordering, Cart, money, payments and Stars.
2. Security and access: who can do what, sign-in, the Second Factor, inputs, headers.
3. Rendering, caching and freshness: does every page show current data.
4. Pages, accessibility and copy.
5. Menu management, Events and Posts, cafe settings, accounts, Staff and emails.
6. Tests, CI (the automatic checks GitHub runs on every pull request) and configuration.

Items already open in the [November audit](2026-11-13.md) (its P3 list, out of scope, refuted) were not reported again.

## 3. What the levels mean

| Level | Meaning | Example |
| --- | --- | --- |
| **P0** | Fix now: an attacker could use it, or money or data could be lost | (none this time) |
| **P1** | Fix next: a real person can get stuck, or broken code can reach the live site unnoticed | Nobody can open `/manage` again |
| **P2** | Fix soon: something works wrongly in a situation that will happen sooner or later | A tablet left open overnight shows yesterday's Sold Out items |
| **P3** | Polish: small, cheap, low risk | A message promises a reply "within two days" on a demo inbox |

## 6. Checked and sound

The reviewers confirmed these hold today:

- **Money:** every amount is whole centavos; formatting goes only through `src/lib/money.ts`; the server prices every Cart, checkout and Order again and ignores totals from the browser; Orders keep a copy of names, Options and prices.
- **Order Status:** every change goes through `transition()`; Capacity is checked under a row lock; cancelling or expiring an Order gives back its window counts and held Stars in the same step.
- **Payments:** webhooks are verified before they are read and counted once; live payment keys are refused; the `fake` provider refuses to run on a real domain.
- **Access:** every Server Action and route checks who is calling. A Barista cannot reach Manager powers; nobody can read or change another person's Order, Cart, Favourites or account; Manager pages ask for the Second Factor; Demo Mode visitors can only move their own Order through the bar's four steps.
- **Sign-in:** unused sign-in routes are switched off; links are stored only as hashes; redirects after sign-in cannot leave the site.
- **Content:** Markdown is shown without raw HTML; uploaded photos are checked by their first bytes and re-encoded without location data.
- **Caching:** every Staff change refreshes the pages it affects; no cached part mixes one person's data with another's; the daily job is safe to run twice.
- **Pages:** the Concept Notice is on every page, including error pages and checkout; no em or en dashes in the copy; every link points to a page that exists; no component or animation library.
- **Earlier fixes:** none of the November audit's fixed items has come back.
